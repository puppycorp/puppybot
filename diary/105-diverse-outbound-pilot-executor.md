# Diverse outbound pilot: paired executor prepared (3 Nov 2026)

Entry 99 identified 12 student/teacher feasibility scenes from six previously
used diverse-room geometries, with no exact case or environment byte match to
the current five-level selection. An isolated pilot now applies the earlier
outbound-only design to those scenes. It stages a fresh common catalog, freezes
its input and launch intent, runs both 300-action level-5 arms separately,
checks complete saved games and teacher labels, and scores every paired case
with the earlier exploratory screen. A screen pass does not authorize training.

The preflight checks all 160 current selection case/environment pairs, records
an ordered digest of their hashes, and verifies seed separation against the
named history and reserved formulas. Source, model, binary, runtime, scene and
monitor hashes are recorded and rechecked. Exact hashes do not prove geometric
or ancestry independence; all six geometries have been used previously, and
the seed scan omits symlinked directories and unrecorded runs. Saved records
and launch intents do not attest execution or raw camera provenance.

Independent review found the previous pilot scorer formed reversal windows
over the entire episode and then clipped the flagged actions to the outbound
prefix. A window crossing pickup could therefore penalize outbound actions
based on later return behavior. The new pilot retains the old saved-shard
checks but scores only windows fully contained before first consumption,
including the window ending exactly at that prefix boundary. If pickup is
missed, the full horizon is the prefix. Its plan and report identify the
measure as `pose20-prefix-bounded-final-inclusive-v1`; historical evidence and
the old pinned auditor remain unchanged. This is still a pose-based heuristic,
not a complete loop detector.

The paired worker and resource-monitor adapter have 20 CPU fixture tests
covering fresh scene/command boundaries, changed selection hashes, existing
output preservation, per-arm failure and partial retention, fresh-process
module reloading, worker input changes, and final-monitor completion behavior.
The prefix tests cover post-pickup contamination, the exact prefix boundary,
an unconsumed episode and the real screen using mocked saved-arm records. One fresh-process check traces the eager local
imports through monitor setup and preflight and verifies all observed local Python modules are pinned;
this does not cover imports reachable only later while processing real outputs.
The earlier nine outbound audit/screen tests and seven resource-monitor tests
also pass. The monitor retains the 30-second GPU baseline, 36/34/32 GiB disk
floors, VRAM thresholds, external process supervision and final inventory.
These tests do not run the real simulator or GPU.

No catalog has been staged, no launch plan frozen, no pilot collected, and no
model trained. The new executor still requires independent source review and a
scheduled GPU run under its monitor. Artifact:
`experiments/outbound-diverse-prefix-pilot-v1/`.
